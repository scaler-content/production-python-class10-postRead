Why this order?You cannot draw a seam you have not found, so the audit comes first. A fake is only fair once the port exists, and the architecture test only means something once the adapters sit outside the core. Working together and review come before the prompt contract and the second vendor, because both of those are changes that other people will touch. The comparison comes last, because it needs every other piece in place, and the requirements for it are written before any result is read.

Which SOLID idea is it?

  

  
The rule that decides itAsk what would have to change. If a module changes for two reasons, it is a single-responsibility problem. If adding a behaviour means editing the core, it is open for extension. If a stand-in behaves differently, it is substitution. If a test needs more than it touches, it is interface size. If the core names a vendor, it is dependency direction.
